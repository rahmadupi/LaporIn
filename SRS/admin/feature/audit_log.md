# Admin Activity Audit Log (Log Aktivitas Sistem)

## 1. Overview
The Admin Activity Audit Log is a headless (backend-only) security and accountability module. It operates entirely via Firebase Cloud Functions to create an immutable ledger of every critical action performed by City Officials. This ensures strict government accountability for report moderation, officer dispatching, and user management without adding computational overhead to the Flutter client.

## 2. Traceability
- **Addressed Gap:** Gap 3 (Admin Activity Audit Log - Who-did-what tracking).
- **Business Rule:** Immutable Accountability (Audit logs cannot be edited or deleted by any user, including Admins).

## 3. UI/UX Requirements
- **No Front-End Implementation:** There is currently zero UI required for this feature in the Flutter Admin application.
- **Silent Operation:** The tracking happens transparently in the background. Admins will not see a loading spinner or confirmation dialog for the audit log creation.
- **Future Scope:** The raw data generated by this module is stored strictly for Firebase Database Administrators or for a future web-based reporting dashboard.

## 4. Database Interactions (Serverless Layer)
- **Target Collection:** `/audit_logs/{logId}`
- **Execution Method:** Firebase Cloud Functions (`onDocumentUpdated`, `onDocumentCreated`). The Flutter client **must never** write to this collection directly.
- **Trigger List:**
  1. `reports/{reportId}` (onUpdate) -> Tracks status changes (Accept/Reject).
  2. `dispatches/{dispatchId}` (onCreate) -> Tracks officer assignments.
  3. `users/{uid}` (onUpdate) -> Tracks user bans (`isActive: false`).
  4. `settings/global/categories/{categoryId}` (onUpdate) -> Tracks category toggles.
